# AI 社交媒体自动化桌面工具 — 产品与技术设计文档

> 日期：2026-10-20 · 阶段：设计定稿（MVP 前置） · 状态：待用户审阅
>
> 本文档整合产品方案（目标用户 / MVP / 技术边界 / 竞品差异）与主界面 UI 设计决策，
> 所有决策均经过用户在 Visual Companion 中的可视化确认。

## 1. 定位与目标用户

**定位：自用工具优先**。不设计多租户、付费与团队协作；架构上不主动封闭未来商业化路径，但不为其增加当前成本。

**目标用户画像**：

> 个人创作者 / 独立开发者，同时在 2 个以上平台（首发：小红书、B站）运营图文账号，
> 有稳定内容领域（如技术科普、AI 工具测评）。痛点：选题耗神、写作耗时、多平台手动分发繁琐，
> 且希望账号内容风格统一、有个人辨识度。

该画像的推论：把两个平台的发布做到稳定可靠，优先于覆盖更多平台。

**核心动线**：配置一次 Agent → 每天 Agent 自动调研选题并生成内容 → 用户在草稿箱花约 10 分钟审阅 → 确认后自动发布。

## 2. 核心功能（MVP）

### 2.1 功能清单

**内容生产链（自动化）**

1. **热点调研** — 定时/手动触发，汇总各平台热榜（适配器 `fetch_trends`），Agent 按领域相关性打分选题。
2. **内容生成** — 选题 → 大纲 → 成文；小红书笔记体 / B站专栏体各一套模板；写作前从 L3 全局记忆召回本人历史帖作为风格样例注入 prompt。
3. **配图生成** — 文生图 API 生成封面图，每篇 1~3 张。

**人机协作边界（唯一必经人工环节）**

4. **草稿审核箱** — 人工审阅、行内编辑、驳回；驳回理由写回 L2 记忆沉淀为 Agent 偏好。

**发布与账号**

5. **自动发布** — 确认后 `execute_publish` 经 Playwright 驱动真实 Chromium 浏览器发布，结构化结果（含错误分类）回写。
6. **账号管理** — 扫码登录、Cookie 会话保持、`check_health` 健康面板展示各平台登录态。

**支撑系统**

7. **Agent 工作台** — 创建/配置 Agent：人设、内容领域、语言风格、目标平台、发布节奏。
8. **三层记忆系统** — 见 §3.3。被用户大幅改写的帖子自动降权，不再作为风格样例。
9. **运行日志** — 每次流水线的完整执行记录与发布历史。

### 2.2 MVP 明确不做（非目标）

视频管线、发布后数据统计回流（需 `fetch_stats`，列为 v2 扩展）、多用户/云同步、自动评论互动、多账号矩阵养号、验证码自动绕过。

## 3. 技术架构与边界

### 3.1 Electron 三进程架构

```
┌─ React UI（Renderer）── 草稿箱/工作台/健康面板；组件级独立测试
├─ Electron Main ──────── 窗口生命周期、IPC 路由、Worker 进程守护；mock Worker 接口测试
└─ Python Worker ──────── Agent 流水线、Playwright、LLM/Embedding 调用；可脱离 Electron 以 CLI 模式跑 pytest
```

- 通信：localhost WebSocket + JSON-RPC，消息携带 correlation id；三层各自 mock 相邻层即可独立测试。
- 取舍：三进程引入 IPC 序列化与进程生命周期管理成本，换取 Python AI 生态、Worker 崩溃不拖垮 UI、每层独立可测。

### 3.2 平台适配器四方法契约

```python
class PlatformAdapter(ABC):
    platform_id: str          # 元数据：平台标识 / 名称 / 能力声明

    def check_health(self) -> HealthReport          # 登录态、依赖就绪性
    def fetch_trends(self) -> list[Trend]           # 平台热榜/趋势
    def compose_post(self, content) -> PlatformPost # 平台规范适配：字数/标签/图片尺寸
    def execute_publish(self, post) -> PublishResult# Playwright 发布
```

- **自动注册**：Worker 启动时扫描 `adapters/` 目录，凡继承 `PlatformAdapter` 且四方法齐全的子类自动注册，UI 从 Worker 拉取适配器列表渲染。第三方贡献新平台 = 实现四方法 + 放入目录。
- **`PublishResult` 错误分类**：登录失效 / 选择器失效 / 平台拒绝。错误类型决定重试策略——登录失效 → 提示重新扫码；选择器失效 → 标记适配器待维护，不盲目重试。
- **人机边界即契约边界**：人工审核插入点位于 `compose_post` 与 `execute_publish` 之间。
- **首发适配器**：`xiaohongshu`、`bilibili_column`（两个适配器验证契约设计）。

### 3.3 三层记忆系统

| 层 | 内容 | 生命周期 |
|---|---|---|
| L1 工作记忆 | 单次流水线运行上下文（当前选题、草稿、召回的参考帖） | 运行结束归档 |
| L2 Agent 记忆 | Agent 配置 + 交互沉淀偏好（如驳回理由形成的风格约束） | 按 Agent 持久化 |
| L3 全局记忆 | 全部历史帖向量库（内容 + 平台 + 是否被人工修改） | 全局持久化，持续累积 |

- **召回时点：写作前**（而非发帖前），历史帖作为 few-shot 样例进入生成 prompt——这是"内容风格一致性"的实现机制。
- **写回时点**：发布完成后，内容与结果写入 L3。
- **降权规则**：被用户大幅改写的帖子自动降权，不再作为风格样例。
- 落地选型：SQLite + sqlite-vec；embedding 走 API。

### 3.4 发布通道与风险边界

- 发布通道：Playwright 驱动真实 Chromium + Cookie 会话，属**非官方通道，不承诺永不失效**；失效影响被适配器层隔离，单平台故障不影响其余链路。
- 风控红线：不自动绕过验证码（触发风控 → 暂停并转人工）；不做多账号矩阵；发布频率可配置限速。
- 数据：全部本地存储（SQLite）；LLM / 文生图 / embedding 均走用户自备 key 的 API；无自建云端。

## 4. 主界面 UI 设计（已可视化定稿）

### 4.1 布局：卡片网格仪表盘

顶栏 + 3 列卡片网格（无侧栏）。卡片：热点雷达 / 流水线状态（五阶段 pill 流）/ 草稿箱（活跃高亮）/ 账号健康 / 记忆库 / 发布历史（跨列 sparkline）。

### 4.2 视觉体系：深色极客风 × 玻璃质感

- 底色 `#05070d`；卡片 `backdrop-filter: blur(14px) saturate(1.3)` + 渐变洗色背景 + 主题色 1px 描边；活跃卡片（草稿箱）带彩色 glow。
- 数字高亮：主题色渐变文字；状态灯：辉光圆点（绿=online / 琥珀=需重登）。
- 静态网格底纹：28px 细线网格叠加。

### 4.3 五变量主题系统

配色由 `--c-primary / --c-secondary / --c-accent / --c-ok / --c-warn` 五个 CSS 变量驱动，运行时可切换。预置 6 套主题：ion 离子 / matrix 矩阵 / ember 熔岩 / synth 蒸汽波 / **frost 冰川（默认，已选定）** / mono 磷光。

### 4.4 动态背景（低运行成本）

三团主题色光晕在底图上缓慢漂移。成本控制手段：

- 柔边由径向渐变本身实现，不用 blur 滤镜；
- 漂移只改 `transform`（GPU 合成线程，不触发重排/重绘），周期 26~34s；
- `prefers-reduced-motion` 时自动静止；
- 卡片毛玻璃为静态一次性渲染，不参与动画循环。

### 4.5 字体：宋体标题 + 等宽数据（混合方案）

- 中文标题 / Logo：衬线宋体，生产环境内置**思源宋体（Noto Serif SC）SemiBold** 网页字体子集（开发预览可用本地 SimSun 回退）。
- 数字 / 日志 / 时间戳 / 标签：Cascadia Code / Consolas 等宽。
- 高级感来自衬线编辑气质与等宽终端气质的对比；放弃全宋体（数据对齐与终端感损失过大）。

### 4.6 轨道时钟（顶栏迷你版，已选定）

- 复刻自 xieka.icu 自研 orbital-clock（逆向分析存于 `C:\Users\LEGION\Nutstore\1\orbital-clock-analysis\`，农历纯函数 `clock_core.js` 可本地复用）。
- **顶栏右侧**：40px 小轨道盘（三针 + 日进度环）+ HH:MM 时间；网格留给数据卡片，农历等信息不在顶栏展示（如后续需要完整版，可在网格内增设时钟卡片，预留该选项）。
- 配色接入主题变量：时针=白、分针=`--c-primary`、秒针=`--c-warn`、日环=`--c-secondary`。
- 成本：每秒一次 JS 更新 4 个 CSS 角度变量，指针走 transform 过渡（合成器线程）。

## 5. 与竞品的差异点

| 竞品 | 它的定位 | 我们的差异 |
|---|---|---|
| Social Auto Upload（开源） | 只自动化"上传发布"环节，视频向 | 我们是调研→写作→配图→审→发全链路 Agent，且图文风格记忆为独有能力 |
| CreBee / 蚁小二类矩阵工具 | 企业多账号分发 SaaS，内容仍靠人写 | 个人创作者本地单机；内容由 Agent 产出；账号凭据不出本机 |
| AiToEarn（开源，最接近） | AI 批量生成 + 多平台分发，矩阵变现导向 | L3 记忆驱动的风格一致性 + 人工审核边界 + 四方法开放契约 |
| Memoraid（浏览器插件） | 网页摘要轻量发文 | 无定时任务、无多账号、无记忆 |

**一句话定位**：现有工具要么"帮你发"（分发工具），要么"帮你写一篇"（AI 写作工具）；没有工具在本地桌面上把"调研→写作→风格记忆→审核→发布"做成闭环，且风格随使用越来越像你自己。

## 6. 测试策略（对应三进程可测性）

- **Python Worker**：脱离 Electron 以 CLI 模式运行，pytest 覆盖流水线各阶段、记忆读写、适配器契约（四方法齐全性校验 + 用录制页面 fixture 测选择器）。
- **Electron Main**：mock Worker 的 JSON-RPC 接口，测 IPC 路由、进程守护与重连。
- **React UI**：组件测试覆盖草稿箱编辑流、主题切换、健康面板渲染。
- **适配器契约测试**：注册表启动时校验每个适配器四方法与元数据齐全，缺一即拒绝注册并报错。

## 7. 风险与开放问题

- 平台改版导致选择器失效：以错误分类 + 待维护标记缓解，接受定期维护成本（自用可接受）。
- Cookie 过期频率未知：`check_health` 常驻监测 + 顶栏状态灯提醒重新扫码。
- LLM 生成内容质量：L3 风格召回 + L2 偏好沉淀 + 人工审核三道闸门兜底。
